# AI-buddy на Railway

Для хакатонного демо нужны сервис приложения и PostgreSQL. Корневой Dockerfile собирает интерфейс, API, агент, MCP и имитатор корпоративной системы. nginx принимает запросы на порту 3000. Перед запуском приложение применяет SQL-миграции к выбранной базе. Используйте отдельную базу для демо.

1. В проекте Railway добавьте PostgreSQL. У существующего сервиса приложения откройте **Settings → Source**. Выберите этот репозиторий и ветку с корневым Dockerfile. Оставьте **Root Directory** пустым. Очистите ручные Build Command и Start Command, если они заданы.
2. В **Variables** приложения задайте значения ниже. Для адреса базы используйте **Add Reference** и выберите внутреннюю переменную DATABASE_URL вашего PostgreSQL.
3. Выполните **Deploy**. После успешной проверки готовности выберите **Settings → Networking → Generate Domain**, target port **3000**. Откройте домен и войдите через «Войти как Анна».

| Переменная | Значение |
| --- | --- |
| PORT | 3000 |
| DATABASE_URL | Ссылка на DATABASE_URL сервиса PostgreSQL |
| JWT_SECRET | Случайный секрет, минимум 32 символа |
| CORP_TOKEN | Второй независимый случайный секрет |

По умолчанию LLM_PROVIDER=mock. Интерфейс обращается к работающему API и агенту. Без Redis агент хранит временное состояние в памяти, поэтому для такого демо используйте одну реплику. Заявки сохраняются в PostgreSQL. Публичный домен предоставляет доступ к синтетическим демо-аккаунтам.

Проверка после выкладки: откройте /api/v1/readyz на домене, затем войдите и отправьте «Что мне делать дальше?» в чате. При ошибке запуска смотрите Deploy Logs: ошибка миграции означает, что нужно проверить подключение к базе. Ошибка распознавания Railpack в Build Logs указывает на выбранную ветку, каталог или настройки сборщика.

Сервис AI-buddy в окружении production проекта earnest-essence подключён к ветке `deploy/railway-demo`. Для выпуска обновления перенесите нужные изменения в эту ветку и отправьте их на GitHub. Ход сборки виден на вкладке Deployments.
