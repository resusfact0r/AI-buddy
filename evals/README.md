# Eval-набор AI-buddy

26 кейсов вида «запрос → ожидаемое поведение»: какой инструмент вызван, пришли ли источники, появилась ли карточка и с какими параметрами, был ли отказ. Каждый кейс ссылается на критерий приёмки из [`specs/`](../specs/README.md).

- [`cases.json`](cases.json) — кейсы.
- [`report.md`](report.md) — отчёт последнего прогона (процент прохождения — для презентации).

## Запуск

```bash
cd agent

# На mock-LLM (без ключа): проверка самого набора и стенда, должно быть 100%
make evals

# На реальной модели
LLM_PROVIDER=openai LLM_BASE_URL=https://openrouter.ai/api/v1 \
LLM_MODEL=openai/gpt-4o-mini LLM_API_KEY=<ключ> make evals
```

Раннер сам поднимает стенд в одном процессе: агент → MCP-сервер → имитация API с синтетическими данными. «Сегодня» зафиксировано на среду, 11 ноября 2026, поэтому даты в кейсах стабильны. Docker и основной API не нужны. Для каждого кейса стенд создаётся заново.

## Формат кейса

```json
{
  "id": "leave-06-followup", "spec": "AC-01-3", "group": "1. Отгул", "user": "intern_anna",
  "before": [{"user": "intern_anna", "message": "Хочу отгул", "confirm": false}],
  "message": "в пятницу",
  "expect": {
    "tools": ["search_knowledge"],
    "no_tools": ["approve_request"],
    "sources": true,
    "proposal": "leave_request",
    "params": {"date_from": "2026-11-13"},
    "contains_any": ["руководител"],
    "not_contains": ["AIB-INTERNAL"]
  }
}
```

| Поле `expect` | Проверка |
|---|---|
| `tools` | все перечисленные инструменты вызваны |
| `no_tools` | ни один из перечисленных не вызван |
| `sources` | `true` — источники пришли, `false` — не пришли |
| `proposal` | тип первой карточки; `"none"` — карточек нет |
| `params` | параметры первой карточки совпадают |
| `contains_any` | в ответе есть хотя бы одна подстрока (без учёта регистра) |
| `not_contains` | ни одной из подстрок в ответе нет |

`before` — шаги подготовки в том же разговоре; `confirm: true` подтверждает карточки этого шага. Событие `error` в ответе всегда считается провалом.
