# 04. Доступы и согласование

## Purpose

Стажёр видит, какие доступы нужны его команде и зачем, что уже выдано и запрошено, и одной карточкой запрашивает недостающие. Руководитель через того же агента согласует заявки.

## Триггеры (примеры фраз)

- Стажёр: «Какие доступы мне нужны?», «Как получить доступ к Grafana?»
- Руководитель: «Что мне согласовать?», «Отклони заявку 104, причина…»

## Нужные данные

| Данные | Откуда |
|---|---|
| Системы команды, назначение, обязательность, статус | `get_access_overview` |
| Заявки на согласование | `list_pending_approvals` (руководитель) |
| Кто согласует | профиль или ответ API |

## Шаги диалога

Стажёр:
1. `get_access_overview` → три группы: уже есть / запрошено / не хватает, по каждой системе — зачем она нужна.
2. Если чего-то не хватает — **одна** карточка `access_request` со всеми недостающими системами и предзаполненной причиной.
3. Пользователь выбирает системы (чекбоксы) и подтверждает → по каждой выбранной `POST /requests/access` с ключом идемпотентности `action_id:system`.
4. Агент сообщает, сколько запросов создано и кто их согласует.

Руководитель:
1. `list_pending_approvals` → список заявок и карточка `approve` на каждую.
2. Подтверждение → `POST /requests/{id}/approve`. Отклонение — «отклони заявку N, причина…» → карточка `reject` с комментарием.

## Инструменты

Чтение: `get_access_overview`, `list_my_requests`, `list_pending_approvals`, `get_request`. Действия: `create_access_request`, `approve_request`, `reject_request`.

## Что требует подтверждения

Создание запросов доступа, одобрение и отклонение заявок.

## Requirements

### Requirement: Обзор и запрос доступов

#### Scenario: AC-04-1 Обзор доступов
- GIVEN у Анны GitLab выдан, Jira запрошена, Grafana, VPN и Kafka UI не хватает
- WHEN она пишет «Какие доступы мне нужны?»
- THEN ответ делит системы на «уже есть», «запрошено», «не хватает» и объясняет назначение каждой

#### Scenario: AC-04-2 Одна карточка
- GIVEN то же состояние доступов
- WHEN агент отвечает на вопрос о доступах
- THEN приходит ровно одна карточка `access_request` с `params.systems = [grafana, vpn, kafka]` и непустой `reason`
- AND `options.systems` содержит название и назначение каждой системы
- AND запросы в API ещё не созданы

#### Scenario: AC-04-3 Подтверждение выбранных систем
- GIVEN Анне показана карточка с тремя системами
- WHEN она подтверждает с `params.systems = [grafana, vpn]`
- THEN созданы ровно два запроса доступа, ответ `status=done` и называет руководителя Елену
- AND повторный confirm не создаёт новых запросов

#### Scenario: AC-04-4 Все доступы есть
- GIVEN у Веры все доступы выданы
- WHEN она пишет «Какие доступы мне нужны?»
- THEN агент говорит, что новых запросов не требуется; карточки нет

#### Scenario: AC-04-5 Частичный сбой
- GIVEN сервис доступов отказывает на первом из двух запросов
- WHEN Анна подтверждает карточку
- THEN ответ `status=partial`: перечислено, что создано и что не получилось, `error.retryable=true`

### Requirement: Согласование руководителем

#### Scenario: AC-04-6 Руководитель одобряет заявки
- GIVEN Анна создала отгул и запросы доступа
- WHEN Елена пишет «Что мне согласовать?»
- THEN агент перечисляет заявки Анны и присылает карточку `approve` на каждую
- AND после подтверждения заявки в статусе `approved`, доступы у Анны `granted`
- AND когда выданы все обязательные доступы, задача «Получить доступы» у Анны закрыта

#### Scenario: AC-04-7 Отклонение и чужая команда
- GIVEN у Анны есть заявка на согласовании
- WHEN Елена пишет «Отклони заявку N, сейчас релиз»
- THEN приходит карточка `reject` с комментарием «сейчас релиз», после подтверждения заявка `rejected`
- AND Фёдор, руководитель другой команды, на «Что мне согласовать?» получает «заявок нет»

## Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| Модель просит доступ к уже выданной системе | система исключается из карточки; если ничего не осталось — карточки нет |
| При confirm не выбрано ни одной системы | `failed`, «не выбрано ни одной системы» |
| API вернул 409 (уже запрошено) | по этой системе ошибка, остальные создаются |
| Отклонение без причины | агент просит причину, карточки нет |
