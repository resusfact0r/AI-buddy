# Материалы Бэк1 для презентации

## Права и безопасность

JWT пользователя проходит через агент и MCP до API. Проверки прав выполняются сервером: стажёр видит свои данные, наставник — планы подопечных, руководитель — свою команду. Руководитель не может согласовать собственную заявку. Статьи чужой команды исключаются из поиска. Доступ к корпоративному моку защищён отдельным токеном; он не заменяет права пользователя в основном API.

Данные полностью синтетические. Статьи имеют is_test_data и текстовую маркировку. Финансовые операции и реальные персональные данные отсутствуют. Пароли хешируются bcrypt, JWT действует 12 часов, Redis ограничивает попытки входа. Идемпотентные запросы не создают повторную заявку.

## Внедрение в инфраструктуру Авито

Цепочка: интерфейс → агент → MCP → API → corpclient → корпоративный сервис. Бэк1 реализует часть от API до корпоративного сервиса; агент и интерфейс подключаются коллегами.

Интерфейс corpclient позволяет заменить тестовый сервис отсутствий и доступов реальными интеграциями. Вместо демонстрационного входа подключается существующая авторизация Авито; права и проверки ресурсов сохраняются. События продукта можно отправлять в Clickstream, изменения заявок — в Kafka, логи и показатели задержек — в Grafana. PostgreSQL хранит состояние, Redis используется для ограничения входа, кэша и повторов запросов.

Демонстрация: запрос отгула → сохранённая заявка pending → согласование руководителем → approved у стажёра. Второй пример: последний обязательный доступ согласован → get_access закрывается автоматически.
